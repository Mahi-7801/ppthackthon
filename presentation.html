✦ SYSTEM ARCHITECTURE
4-Tier Hardware-to-Cloud Architecture
03 / 10
Layer 1: Native USB CCID Driver (Kotlin)
  • Interfaces directly with Android USB Host APIs (android.hardware.usb).
  • Implements ISO/IEC 7816-4 APDU transport over USB Bulk IN/OUT (Class 0x0B).
  • Auto-discovers endpoints, claims interfaces, and handles watchdog timeouts.
Layer 2: PKCS#11 Cryptographic Engine
  • Hardware RSA 2048/4096 & ECDSA signing inside FIPS 140-2 Level 3 Secure Element.
  • Private keys NEVER leave hardware token (Only SHA-256 hash sent, signature returned).
  • Direct hardware PIN verification with instant memory wipe (pinBytes.fill(0)).
Layer 3: Cross-Platform Mobile Client (React Native)
  • Custom Native Module (DSCSigningModule) with real-time event listeners.
  • On-device PDF picking, SHA-256 calculation, and visual signature placement.
  • Built-in CCA Sandbox Simulation Mode for testing without physical tokens.
Layer 4: Cloud PAdES Assembly & Audit (Node.js/Supabase)
  • RFC 3161 Time Stamping Authority (TSA) injection for Long-Term Validation (LTV).
  • Packages PAdES (ETSI EN 319 142) and CAdES compliant digital signature containers.
  • Immutable Supabase PostgreSQL audit log storing signer serial, hash, and timestamp.
✦ OPERATIONAL WORKFLOW
Seamless 8-Step Mobile Signing Flow (< 30s)
04 / 10
Step 1: Auth & Login

Officer logs into SecureSign via Supabase JWT Bearer authentication.

Step 2: Plug & Detect

Type-C DSC dongle plugged in; instant automatic USB enumeration.

Step 3: Hardware PIN

PIN verified directly on-chip via APDU; memory cleared immediately.

Step 4: Pick Document

Approval PDF selected; local SHA-256 hash computed on-device.

Step 5: Hardware Sign

Hash sent to token; private key signs inside isolated secure element.

Step 6: RFC 3161 TSA

Backend submits signature to TSA for official cryptographic timestamp.

Step 7: PAdES Assembly

Signature + timestamp sealed into PDF forming legally valid PAdES-LTV.

Step 8: Verify & Share

Signed PDF downloaded and shared via WhatsApp, Email, or e-Office.

✦ REGULATORY COMPLIANCE
100% CCA India Guideline Compliance Matrix
07 / 11
✔ Rule 1: Private Key Security
Signing operation occurs strictly inside hardware secure element. Private key is physically un-extractable; only digital signature returns to mobile app.
✔ Rule 2: PIN Isolation & Zero Memory
PIN is transmitted directly via APDU commands to token hardware. Zero plaintext storage; memory buffer is instantly wiped with pinBytes.fill(0).
✔ Rule 3: PAdES-LTV with RFC 3161 TSA
All generated PDFs contain standard PAdES-LTV containers with cryptographic timestamps from licensed Time Stamping Authorities.
✔ Rule 4: Hardware PIN Lockout Counter
Token hardware enforces strict 3-attempt PIN retry policy. Accidental lockout prevents brute-force tampering.
✔ Rule 5: Tamper-Evident Audit Trail
Every transaction logged with Signer ID, Certificate Serial Number, Document SHA-256, TSA Token, and Client IP in Supabase PostgreSQL.
